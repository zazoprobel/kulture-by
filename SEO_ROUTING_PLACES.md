# SEO/CHPU для списка `places`

## Что хотим получить
1. У страниц списка мест (`/places`) должны быть корректные SEO-метаданные: `title`, `description`, `canonical`.
2. При выборе фильтра категория/город формируют ЧПУ URL (без query-параметров).
3. Пагинация должна быть частью URL: `.../page/2`.
4. “Слабые” страницы с маленьким числом результатов должны получать `noindex`.

## Принятые правила по URL (как договорились)
1. Порядок сегментов фиксированный.
2. **В URL участвуют только:**
   - категория (`/places/priroda`)
   - город (только один, без комбинирования): `/places/priroda/minsk`
3. **Не участвуют** в URL:
   - стоимость входа
   - рейтинг
   - сортировка
4. Пагинация:
   - страница 1: без `/page/1`
   - страница N: `.../page/N`
5. `canonical` всегда указывает на конкретную страницу пагинации (например `.../page/2`).
6. `noindex` (через `robots.index=false`), если результатов **меньше 12** (`totalCount < 12`).

## Примеры ожидаемых URL
- Все места (база): `/places`
- Категория “Природа”: `/places/priroda`
- Природа + Минск: `/places/priroda/minsk`
- Пагинация: `/places/priroda/minsk/page/2`

## Реализация (что именно добавлено/изменено)

### SEO-шаблоны и маппинги сегментов
- `lib/seo/places.ts`
  - маппинг CHPU сегментов категорий/городов ↔ значения в БД
  - генерация шаблонов `title/description`
  - функция построения canonical-пути `placesCanonicalPath(...)`
- `lib/seo/placesData.ts`
  - серверная выборка списка с `limit/offset` через Supabase `range()`
  - отдельная выборка `totalCount` для расчёта пагинации/`noindex`
- `lib/seo/siteUrl.ts`
  - получение абсолютного `siteUrl` из `NEXT_PUBLIC_SITE_URL` или заголовков запроса

### Клиентская часть: перевод фильтров в ЧПУ URL
- `components/places/PlacesCatalogClient.tsx`
  - добавлен `router.push()` при смене **категории** и **города** (в CHPU-части)
  - вход/рейтинг/сортировка **не меняют URL**, но меняют контент внутри страницы (по вашим правилам)
  - пагинация уводит в `/page/N` и при этом поддерживает совпадение URL ↔ server-rendered SEO-части

### Серверные SEO-роуты для списка `places`
Обновлён и добавлены следующие страницы:
- `app/places/page.tsx`  
  - `generateMetadata()` для `/places`
- `app/places/page/[page]/page.tsx`  
  - `generateMetadata()` для `/places/page/2` и т.д.
- `app/places/[slug]/page.tsx`  
  - `generateMetadata()` и “двойной режим”:
    - если `slug` = реальный slug места — это детальная страница места
    - если `slug` = CHPU-категория — показывается каталог по категории (как SEO-страница)
- `app/places/[slug]/[city]/page.tsx`  
  - каталог по категории + городу (пример `/places/priroda/minsk`)
- `app/places/[slug]/page/[page]/page.tsx`  
  - каталог по категории + пагинация
- `app/places/[slug]/[city]/page/[page]/page.tsx`  
  - каталог по категории + городу + пагинация

## Canonical (как формируется)
`canonical = ${siteUrl}${placesCanonicalPath(...)}`, где:
- базовый путь зависит от выбранных сегментов (`/places`, либо `/places/<category>`, либо `/places/<category>/<city>`)
- для страниц `page > 1` добавляется `/page/<page>`

## Важное замечание (остаточный риск)
Так как `вход/рейтинг/сортировка` **не участвуют** в URL, контент внутри страницы может меняться при взаимодействии пользователя, но `canonical` остаётся прежним (соответствует SEO-части URL). Для SEO это обычно ок, потому что поисковые боты редко “кликают фильтры”, а рендер по URL фиксирован.
